# 图尔敏：把 Warrant（保证）写出来

论证不只是「有数据」和「有结论」。从数据跳到结论之间，往往缺一层**保证（warrant）**——凭什么这个事实能支持这个主张。

## 最小六件套（按需展开）

| 要素 | 问什么 |
|---|---|
| **Claim（主张）** | 你要读者接受什么？ |
| **Data / Grounds（依据）** | 依据是什么事实、数据、观察？ |
| **Warrant（保证）** | 依据凭什么能推出主张？ |
| **Backing（支撑）** | 保证本身靠什么站得住？（可选） |
| **Qualifier（限定）** | 主张有多强？在什么范围内成立？ |
| **Rebuttal（反驳/例外）** | 什么情况下主张不成立？（可选） |

知识工作文档里，最常缺的是 **Warrant** 与 **Qualifier**：有表、有结论，中间的逻辑桥是暗含的。

## 操作

对每个核心论断问：

1. 依据是哪一句/哪张表？  
2. **保证是什么？**（例如：该样本可代表目标人群；该指标上升等于效率提升）  
3. 读者会接受这个保证吗？不接受 → 补 backing，或降低声称（`proportion`）  
4. 改口条件写了吗？（探索驱动尤其需要）

## AI 初稿常见病

- 「因此 / 由此可见」没有真实推导，只是语气连接  
- 把「来源真实」当成「材料适用」，再当成「应该立刻行动」  
- demo 跑通 → 可推广（缺 warrant，且伤否决「过度声称」）

## 边界

- 不是每句话都要画满六格；**核心主张**才强制检查 warrant。  
- 图尔敏是拆解工具，不是万能大纲模板。  
- 与 `logic` / `sources` / `proportion` 直接相连；结构安排仍见 [structure.md](structure.md)。
