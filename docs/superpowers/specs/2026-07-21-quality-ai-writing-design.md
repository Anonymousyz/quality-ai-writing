# 《高质量 AI 写作》设计文档

**仓库名：** `quality-ai-writing`  
**中文名：** 高质量 AI 写作  
**日期：** 2026-07-21  
**状态：** 已确认（含收录范围）  

---

## 1. 定位

AI 让第一稿的成本趋近于零。这部作品回答的问题是：

> 署名前，一篇知识工作文档怎样才算高质量？

它是一套**可更新的评审标准**，配脱敏修改判例与中英写作传统打底。不是 prompt 技巧集，不是去 AI 味插件，也不是创意写作教材。

**管辖范围：** 方案、评审、报告、决策备忘、README 与技术文档等知识工作文档；中英文通用。  
**不管：** 创意写作、营销文案工坊、通用 prompt 库。

**受众与成功标准：** 自用为主，公开作为判断力/品味证据。成功 = 自己持续在用、标准被案例驱动修订过几轮、外人读判例能看出取舍。不追 star，不承诺更新频率。

**与 humanizer 类工具的关系：** 去 AI 味只覆盖辞章层的一部分。本作品覆盖立意、逻辑、来源、分寸、字句、文气、得体的完整署名前判断。

本仓库定位为**可公开的评审标准与脱敏示范**。「规则接受真实检验」体现为判例驱动修法。

## 2. 架构

单仓库「活标准」：

| 层 | 角色 |
|---|---|
| 标准（成文法） | `STANDARD.md`：一票否决 + 三层八维 + 终审 |
| 原则详解 | `principles/`：每维一文件 |
| 判例 | `cases/`：脱敏后的第一稿→定稿对照 |
| 收件箱 | `inbox/`：本地草稿，gitignore，不进公开仓 |
| 传统打底 | `traditions/`：中英名篇与 AI 写作的映射 |
| 入库技能 | `skills/case-intake/`：把改前改后整理成案例草稿 |
| 修法记录 | `CHANGELOG.md`：每次修订注明依据案例 |

演化：标准在判例中稳定到 v1 后，可另拆「写作评审卡」技能仓（对标 `ai-launch-red-team`），首版不做。

## 3. 标准框架

### 3.1 一票否决（先扫，触发即不合格）

1. 关键事实错误或编造（含编造引文、数据、来源）  
2. 关键论断来源不可溯  
3. 过度声称：demo 说成结论、个例说成规律、未验证说成已验证  
4. 场合违规：敏感信息、未授权引用  
5. 通篇无人的判断：AI 初稿直接交付，看不到立意与取舍痕迹  

### 3.2 三层八维

借桐城派「义理、考据、辞章」组织：

**义理——想清楚了没有**

1. **立意**：有没有一个值得写下来的判断？删掉这篇，决策会不会变差？  
2. **逻辑**：结论是从证据里长出来的，还是先有结论再找话？  
3. **取舍**：详略即观点；广度是被选择过的。  

**考据——站得住没有**

4. **来源**：关键事实、数据、引文可溯源；来源权威且被正确转述。  
5. **分寸**：声称强度与证据强度匹配。  

**辞章——写干净没有**

6. **陈言务去**：套话、空话、AI 腔一律去掉；每句话须有信息量。（中文例：「赋能」「值得注意的是」；英文例：delve、"It's not just X, it's Y"）  
7. **文气**：句子长短、节奏、段落衔接；一口气读下来是否断气。  
8. **得体**：语体与场景匹配；中文是地道中文，英文是地道英文，不是互相的翻译腔。  

### 3.3 终审

八维查毕，清单结束。最后成不成——没有任何清单能替判断者做。

> 文章千古事，得失寸心知。

品味不设检查项。标准以上句立利害，以下句收卷。

每个 `principles/*.md` 含：定义、评审问句、AI 初稿典型病征、改法、中文出处、英文出处、关联判例。

## 4. 收录范围（硬约束）

原则：**仓库只收录可迁移的判断框架与已脱敏示范；不收录未脱敏真料。**

| 材料 | 是否收录 | 规则 |
|---|---|---|
| 标准维度、评审问句、一票否决 | 是 | 骨架可被复制；判断力在持续修法 |
| 中英传统短摘 + 映射 | 是 | 短摘、注出处；不收录长篇笔记原文 |
| 案例 | 仅脱敏/虚构判例 | 含可识别客户/雇主/项目信息时禁止入库 |
| `inbox/`、改前改后原文、修法草稿 | 否 | gitignore；不进版本库 |
| CHANGELOG | 只写结论 | 「因某类病征修订」；不引用可识别原文档 |

**入库决策规则：** 删掉人名、项目名、内部数字后，仍保留可示范的取舍 → 可改写成公开判例；删完只剩空壳，或仍能被认出真实来源 → **禁止入库**。

**README 必写：** 本仓库包含什么 / 不包含什么（标准与脱敏示范 vs 未脱敏材料与未发表台账）。

**许可：** 代码 MIT；标准/原则/案例/传统文本 CC BY 4.0（署名义务即产权信号）。

## 5. 案例与更新循环

### 5.1 判例格式

`cases/YYYY-MM-DD-slug.md`，front-matter：场景、维度标签、一句话判词。  
正文：场景说明 → AI 初稿片段 → 修改稿 → 逐处改动对应维度。

### 5.2 收件箱与脱敏

- `inbox/` 整体 gitignore（保留说明 README）。  
- 入库红线：案例必须虚构化；不含真实客户、雇主、项目数据。  
- 首版 3 个种子案例（虚构典型场景构造）。

### 5.3 入库技能 `skills/case-intake`

输入改前改后两段 → diff 分析 → 改动归维度 → 生成案例草稿 → 脱敏扫描（专名、数字、内部系统名标红）→ 备注「此案例暗示标准哪里可能要修」。人只审校确认。  
安装方式同其他 Agent 技能（clone 到 Cursor / Claude Code / Codex skills 目录）。

### 5.4 修法

每攒约 10 条案例或每季度：看哪些维度案例最密、哪些病征未被标准接住、**哪条原则从未被判例引用（考虑降级删除）**。  
`STANDARD.md` 带版本号；CHANGELOG 每条修订注明依据案例 ID（公开 ID，无可识别原文档名）。

## 6. 传统打底层

`traditions/`，每篇 500–1500 字：短摘注出处 + 提炼 + 对 AI 写作的映射。

**已有（v0.2）：**

1. 韩愈《答李翊书》  
2. Orwell《Politics and the English Language》  
3. 《文心雕龙·熔裁》  
4. 余光中《中文的常态与变态》（要旨映射）  
5. Strunk & White《The Elements of Style》  
6. Zinsser《On Writing Well》  

**过程短注（v0.3）：** `notes/` — 任务模式、结构、修改顺序、一段一意、读者优先、理解天花板、场景化选择；`MAINTENANCE` 含规则准入四条。  

**传统篇（v0.5 起 13 篇）：** 上列 + 陆机《文赋》、苏轼辞达、桐城义法。  

**技能：** `ai-prose-detect` · `mock-reader` · `case-intake`。  

**过程工具短注：** 图尔敏 Warrant、MECE 等。  

**路线图候选：** 更多种子判例；检测规则的轻量脚本化；场景子集（研究引言 CARS 等，可选）。

## 8. 非目标（YAGNI）

- 不做文档站 / mdBook（首版 GitHub Markdown 即可）

- 不做创意写作覆盖
