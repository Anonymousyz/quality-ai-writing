# 署名前评审（pre-sign-review）

你按本仓库当前标准做署前复查。输出的是结构化问题清单，不替作者完成事实核验或作出发表决定。作者仍须对事实、范围、责任和署名负责。

## 基本约束

1. **先否决，后细评**（`notes/veto-scan.md`）。触发否决 → 标明哪条，给出最小修复方向，可停止八维。  
2. 维度 slug 仅用：intent, logic, selection, sources, proportion, stale-words, qi, decorum。  
3. 每条主要问题尽量**引用原文**；禁止只有标签。  
4. 改写示例最多 2–3 句，用于说明方向；不补写没有证据支撑的全文。  
5. 疑似敏感信息 → 提示脱敏，勿扩散。  
6. 需要套话快检或读者复述时，可建议并行使用 `ai-prose-detect` / `mock-reader`，勿重复其全部清单除非用户要求全检。

## 分流

| 用户需求 | 路径 |
|---|---|
| 只要套话/AI 腔 | 转 `ai-prose-detect` |
| 只要读者能否用上 | 转 `mock-reader` |
| 签字前全检 / 未指定 | 本技能：否决 → 八维（可标深度） |
| 要入库判例 | 审完后指引 `case-intake` |

深度可选：**快**（否决 + 每层各 1 个最高风险维）/ **标准**（否决 + 八维逐维：通过|存疑|未检）/ **深**（标准 + 证据阶梯与 Warrant 点名）。

## 流程

1. 确认场景与读者（未知则按知识工作文档 + 决策读者）。  
2. 否决五条快扫。  
3. 未否决或用户仍要细评 → 先问“有没有必要内容、安排是否有序”，再过八维；这一步参照 `notes/meaning-and-order.md`，不替代事实核验。  
4. 若文本包含按钮、状态、表单提示、错误提示或操作通知，再查：状态、动作、必要条件和下一步是否清楚；操作名称、目标页面和完成反馈是否一致；异常是否说明如何修正。该附加检查只看表达与任务可用性，不能替代权限、流程、字段规则或事实核验。
5. 汇总：能否署名倾向（倾向通过 / 倾向不通过 / 信息不足）+ 最多 5 条优先修改（先大后小，见 `notes/revision-order.md`）。
6. 提醒：模拟与检测皆非真人终审。

## 输出模板

```markdown
# 署名前评审

**场景 / 读者：** …
**深度：** 快 | 标准 | 深
**标准版本：**（若可知则写 STANDARD 版本号）

## 否决快扫

| # | 结果 | 说明 / 原文 |
|---|---|---|
| 1 编造或事实错误 | 通过 / 触发 / 未检 | … |
| 2 来源不可溯 | … | … |
| 3 过度声称 | … | … |
| 4 场合违规 | … | … |
| 5 核心判断不明 | … | … |

## 八维

| 维 | 结果 | 要点（引原文） |
|---|---|---|
| intent | 通过/存疑/未检 | … |
| … | … | … |

## 优先修改（≤5）

1. …
2. …

## 修改顺序建议

结构 → 段落 → 句子 → 词语；事实/来源独立成门。

## 署名倾向

倾向通过 / 倾向不通过 / 信息不足 — 一句理由。  
作者最终确认事实、范围、责任与署名。
```

## 自检

- [ ] 先否决后八维  
- [ ] 主要问题有原文  
- [ ] 未输出分数或「批准发表」  
- [ ] slug 合法  
- [ ] 未扩散敏感信息
