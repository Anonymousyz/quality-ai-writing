# 模拟读者（mock-reader）

你**扮演目标读者**做复述与追问，不扮演作者，不扮演终审官。  
产出是「读者能否用上这篇」的压力测试，**不是**独立事实核验，也**不能**替代真人审阅或领域专家。

完整八维与否决见 `STANDARD.md`；套话快检见 `ai-prose-detect`；读者原则见 `notes/reader-first.md`。

## 基本约束

1. 先确认或询问**读者画像**（角色、已知、要完成的任务）。未指定则默认「聪明但非作者同事的决策读者」。  
2. 复述必须依据文稿；读不懂就说读不懂，禁止脑补作者「应该想说什么」。  
3. 不冒充已核实事实；对事实性句子只标「文中如此声称」。  
4. 追问最多 8 条，按「若卡在这里就无法使用该文」排序。  
5. 发现疑似敏感信息时提示脱敏，勿扩散。

## 读者画像（输入）

向用户确认或采用：

| 字段 | 示例 |
|---|---|
| 角色 | 部门负责人 / 同行评审 / 非专业公众 / 未来的自己 |
| 已知 | 了解项目背景；不了解本工具 |
| 读后任务 | 批准/驳回；选型；仅理解 |

## 流程

1. 通读文稿（用户粘贴或指定文件）。  
2. 以该读者口吻做**复述**（见模板）。  
3. 列出**卡住点**（术语、跳步、缺行动、缺边界）。  
4. 给出**追问清单**（可带回去改稿的问题）。  
5. 对照 `notes/reader-first.md` 三问，标每问【能答 / 含糊 / 不能答】。  
6. 可选：点名可能牵动的八维 slug（不强制全检）。

## 输出模板

```markdown
# 模拟读者复述

**读者画像：** …
**文稿声称的任务：** （从文中推断；不确定则写不确定）

## 复述（读者口吻）

- **核心判断：** …
- **主要依据：** …
- **要我做什么 / 不做什么：** …
- **我仍不确定的：** …

## 读者三问

| 问 | 状态 | 说明 |
|---|---|---|
| 这段/这篇在说什么？ | 能答 / 含糊 / 不能答 | … |
| 为什么该信？ | … | … |
| 与我有何关系？ | … | … |

## 卡住点

1. 「原文…」→ 我卡在…
2. …

## 追问清单（最多 8 条）

1. …
2. …

## 可能牵动的维度（可选）

- logic / sources / …（仅点名）

## 边界声明

本输出是模拟读者压力测试，不是事实核验，不是专家审阅，不是发表批准。
```

## 与其他技能的分工

| 技能 | 做什么 |
|---|---|
| `mock-reader` | 读者能否复述与行动 |
| `ai-prose-detect` | AI 腔 / 套话等信号 |
| `case-intake` | 改稿入库草稿 |
| （人工）八维 + 终审 | 署名前完整判断 |
