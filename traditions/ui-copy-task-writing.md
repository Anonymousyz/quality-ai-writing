# Ant Design：界面文字服务于用户任务

## 出处

[Ant Design《文案规范》](https://ant.design/docs/spec/copywriting-cn/)（官方中文文档）。本页只转述与知识工作产品相关的检查问题，不替代产品的领域规则、可访问性要求或法律告知。

## 文字是操作的一部分

用户读按钮、状态、提示和错误信息，是为了完成一件事。界面文案要先回答用户此刻最关心的问题：发生了什么、会有什么影响、现在可以做什么、做完会怎样。

这对应 `decorum` 与 `selection`：语气、术语和信息顺序要合场景；不要让产品自我介绍挤占用户需要的动作信息。

## 四项检查

### 1. 动作明确

按钮用动词和对象命名，例如“保存草稿”“提交复核”。操作名称、目标页面和完成反馈使用同一个词，避免“确定”“处理”等脱离上下文的按钮。

### 2. 状态可辨

区分未开始、处理中、已完成、部分完成与无法完成。不要把不同原因都压成“失败”或“暂无内容”。

### 3. 信息前置

把用户最需要处理的信息放在开头。帮助文字只补充格式、范围、用途或限制，不重复用户已经看见的内容。

### 4. 异常给出下一步

错误提示应说明发生了什么、用户如何修正；无法自助时，再说明可联系的对象。不要指责用户，也不要用模糊的“操作失败”结束。

## 边界

- 任务文案重视清楚和可操作，不追求辞藻。
- “用户优先”不意味着隐藏风险、责任或必要限制；高风险操作应先说明对象和后果。
- 专业用户可以看到必要术语，但同一对象、状态和动作必须前后一致。
